## 検証エビデンス
### 1. バックエンド E2E（直接 :8080）
登録 → ログイン(JWT 発行) → タスク作成 → 一覧 → in_progress へ移動 → 完了 → 削除 → 未認証 401、
の全ステップを実 HTTP で通した。
- POST /users = OK、POST /login = token 取得
- POST /tasks = id=14 / status=todo、GET /tasks = 1 件
- PATCH /tasks/{id} = in_progress、PATCH /tasks/{id}/complete = done + completed_at セット
- DELETE /tasks/{id} 後 GET /tasks = 0 件
- トークン無し GET /tasks = **401**（認証ガード動作）

### 2. CORS 実挙動（:8080）
- OPTIONS /tasks（Origin: http://localhost:5173）= **204**、
  Allow-Origin=`http://localhost:5173` / Allow-Methods=`GET, POST, PATCH, DELETE, OPTIONS` /
  Allow-Headers=`Authorization, Content-Type`。
- 不許可 Origin(evil.example.com) には Allow-Origin **付与なし**（正しく拒否）。

### 3. フロント経路（Vite :5173）
- GET / = 200、`<div id="root">` と `/src/main.tsx` エントリを配信。
- GET /api/tasks（無トークン）= **401**（プロキシがバックエンド認証に到達）。
- /api 経由で 登録 → ログイン → タスク作成(id=15) → 一覧(1 件) の通しが成功。
