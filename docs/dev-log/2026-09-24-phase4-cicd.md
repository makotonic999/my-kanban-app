# dev-log: 2026-09-24（フェーズ4 続き）— CI/CD（GitHub Actions）

## この日やったこと
GitHub Actions で CI/CD を構築。**CI は即稼働**（AWS 不要・課金なし）、
**CD は OIDC（シークレットレス）でコード化**し、インフラ `apply` 後に有効化する段階構成にした。

## 実装
### CI（`.github/workflows/ci.yml`）— push / PR
- job `go`: gofmt チェック → `go vet` → `go build` → `go test -race -coverprofile` → カバレッジ要約。
- job `terraform`: `fmt -check -recursive` → `init -backend=false`（クレデンシャル不要） → `validate`。
- `concurrency` で同一 ref の古い実行をキャンセル。

### CD（`.github/workflows/cd.yml`）— main push / 手動
1. `aws-actions/configure-aws-credentials@v4` で **OIDC ロールを assume**（`permissions: id-token: write`）。
2. ECR ログイン → `docker build` → `sha` と `latest` タグで push。
3. `amazon-ecs-render-task-definition` で現行タスク定義に新イメージを差し込み → `amazon-ecs-deploy-task-definition` で更新（安定待ち）。
- `if: vars.AWS_ROLE_ARN != ''` で、ロール未設定時は安全に skip（インフラ未構築での誤爆防止）。
- path フィルタでアプリ関連の変更時のみ起動。

### OIDC IAM ロール（`terraform/oidc_github.tf`）
- `aws_iam_openid_connect_provider`（token.actions.githubusercontent.com）。
- ロールの信頼ポリシーを **`repo:makotonic999/my-kanban-app` の main/タグに限定**（最小権限の入口）。
- 権限: ECR 認証/ push、ECS デプロイ、ECS ロールへの `iam:PassRole`（`PassedToService=ecs-tasks` 条件付き）。
- `enable_github_oidc`（既定 true）でトグル可能。`output github_actions_role_arn`。

### デプロイ阻害要因の修正
- `cmd/api/main.go`: `godotenv.Load()` を **致命的エラーにしない**（ECS では環境変数が SSM 由来のため）。
- `Dockerfile`: `COPY .env .` を削除（`.env` は gitignore でありビルドが壊れる。機密は SSM から注入）。

## セットアップ（CD 有効化手順・apply 後）
1. `cd terraform && terraform apply`
2. `terraform output github_actions_role_arn` の ARN を取得
3. GitHub リポジトリ → Settings → Secrets and variables → Actions → **Variables** に
   `AWS_ROLE_ARN` として登録
4. 以降 `main` への push で CD が自動実行される

## 学びのポイント
- **OIDC でシークレットレス**: GitHub に長期 AWS キーを置かない。実行時に短命クレデンシャルを assume。
  信頼ポリシーの `sub` 条件で「どのリポジトリ/ブランチから来たか」を検証するのが肝。
- **CI と CD の分離**: CI は環境非依存で常時緑にできる。CD は実インフラ前提なのでゲートを設ける。
- **12-factor 的なコンテナ**: 設定はイメージに焼き込まず環境変数（SSM）から。`.env` 依存を外した。

## 追記: CI 初回失敗 → 修正 → グリーン確認（重要な学び）
初回 push で CI が **失敗**（gofmt チェック）。原因と対処:
- **原因A（gofmt）**: Windows で作成したファイルが **CRLF** 改行で、Linux ランナーの `gofmt` が
  全ファイルを「未整形」と判定。→ `.gitattributes` で `*.go` などを **LF 強制**（`.ps1` は CRLF）、
  `gofmt -w` で正規化、`git add --renormalize` で再登録。
- **原因B（テストの非決定性）**: `TestValidateToken_Tampered` が署名末尾1文字を書き換える実装で、
  base64url 末尾ビットの都合で稀に同一デコードとなり検証が通ってしまい **flaky** だった。
  → ペイロード先頭を確実に書き換える方式に修正（ローカルで 5/5 連続 PASS を確認）。
- **結果**: 修正 push 後の CI 実行 `35966732602` / PR 実行 `35966738904` はいずれも
  **completed success**（Go build & test + Terraform checks の両ジョブ緑）。GitHub 上で実証済み。

> 教訓: 「ローカルで通った」だけでは不十分。CI は別 OS(Linux)・別条件(`-race` は CGO 必須)で走るため、
> 環境差（改行コード・CGO）と非決定なテストは CI で初めて露見する。CI を回して初めて"証明"になる。
