### ハマりどころ（重要）
- **`-UseBasicParsing` 必須**: ヘッドレスで `Invoke-WebRequest` がレスポンス本文を安定取得できず、
  `.id` / `.token` が空になった。全リクエストに付与して解決。
- **UTF-8 (BOMなし) + 日本語コメントの誤読（根本原因）**: Windows PowerShell 5.x が
  BOMなしファイルをANSIとして誤読し、ユニークsuffix生成が間欠的に空文字化 → 空メール重複で失敗。
  → スクリプトを **ASCIIのみ**に書き換え、空suffixガードを追加して恒久修正。
  - 教訓: PowerShell 5.x 向けスクリプトは **BOM付きUTF-8** か **ASCII** で保存する。

# dev-log 追記: 2026-09-24（午後）— 認可（Authorization）の実装

## 背景
午前の JWT は「認証（誰か）」まで。「認証済みなら他人のタスクも操作できてしまう」バグが残っていた。
これを塞ぐ認可を実装した。

## 実装方針（設計判断）
- **source of truth はトークン**: 所有者や一覧フィルタは、リクエストボディやパスの user_id ではなく
  JWT 由来の userID（`middleware.UserIDFrom(ctx)`）で決定。なりすまし防止。
- **他人のリソースは 404**（403でなく）: リソースIDの存在有無を漏らさない流儀で統一。

## 変更
- `internal/middleware/auth.go`: `UserIDFrom(ctx)` ヘルパ追加（型安全に userID を取り出す）。
- `internal/handler/task.go`:
  - `List` → `WHERE user_id = $1`
  - `Create` → ボディの user_id を無視、トークンの userID で INSERT
  - `GetByID`/`Update`/`Delete`/`Complete` → `AND user_id` で絞り、非該当は 404
  - `AddTag` → `INSERT ... SELECT WHERE EXISTS(自分のタスク) AND EXISTS(自分のタグ)` + 所有権再確認で404
  - `RemoveTag` → `EXISTS(自分のタスク)` を満たす場合のみ削除
- `internal/handler/tag.go`: `List` はトークンの userID（パス引数を廃止）、`Create`/`Delete` も所有者スコープ。
- `cmd/api/main.go`: `GET /users/{user_id}/tags` → `GET /tags`。
- テスト: 認可ユニット6件 + `TestUserIDFrom` を追加（計23件）。`test-auth.ps1` を12チェックに拡張。
- ドキュメント: `docs/openapi.yaml`（`GET /tags` に統合、Create系から user_id 除去、認可の404を明記）、
  README にテスト&品質セクション追加、`docs/TEST_EVIDENCE.md` セクション7追加。
